# 代码结构

## 运行方式

栖页是无构建依赖的静态应用。`index.html` 按顺序加载普通脚本，既支持 `file://`，也支持 HTTP/HTTPS 静态托管。Node.js 与 jsdom 只用于开发检查；发布包不包含测试依赖。

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构、表单、弹窗、脚本加载顺序和无障碍标注 |
| `core.js` | 默认配置、URL / 备份校验、文件夹结构、搜索、主题和时间计算；导出 `QiPageCore` |
| `engine-icons.js` | 白名单内联 SVG 图形，导出 `QiPageEngineIcons` |
| `app.js` | 主页状态、持久化、网址与文件夹操作、组件、网络请求、主题和壁纸 |
| `layout.js` | 布局切换、搜索焦点、Dock 动效、滚动和右键交互；导出 `QiPageLayout` |
| `style.css` / `layout.css` | 基础样式与布局、Dock、响应式行为 |
| `chrome-extension/bookmark-tree.js` | 主页与扩展共用的书签树选择逻辑 |
| `chrome-extension/` | 独立 Manifest V3 主页入口与书签导出扩展 |
| `assets/` | 本地图标、默认风景与素材许可 |
| `tests/` | Node 核心测试、jsdom 交互与 Chrome API 模拟 |
| `scripts/` | 语法检查与发布目录生成 |

## 数据流

1. `core.js` 创建默认值，`app.js` 读取 `qipage.v1` 本地状态并通过 `validateBackup` 校验和补齐字段。
2. 用户操作修改内存状态，再由统一持久化流程写回 localStorage、更新对应界面。存储失败会显示提示。
3. 壁纸文件通过 IndexedDB 保存，页面使用临时对象 URL 展示；本地取色不上传图片。
4. JSON 恢复先完整校验，再确认替换。浏览器书签导入预览后追加，跳过重复网址并保留已有数据。
5. 布局层通过现有全局接口与 `qipage:*` 自定义事件和应用协作。修改接口须同时检查调用方与交互测试。

主页最多保存 500 个网址、100 个 Dock 文件夹和 30 个分组，文件夹最多 32 层。修改结构校验时须保留容量检查、引用完整性和循环检测。

## 扩展边界

扩展保存独立的 `chrome.storage.local.targetUrl`，不直接访问主页 localStorage。未配置时在当前标签页打开设置；保存本地路径或 HTTP/HTTPS 地址后，新标签页、工具栏按钮和主页入口共用该地址。旧配置保留。

常驻权限为 `storage` 与本地文件主机权限。书签权限仅在用户点击读取时申请，代码只调用书签树读取接口；通过本地 JSON 文件导入主页。扩展 CSP 禁止脚本联网，不影响导航到目标页面。

## 测试与发布

`npm run verify` 是本地与 CI 的统一检查入口。核心测试覆盖 URL 校验、搜索、备份与迁移、主题、计时和书签树；jsdom 测试执行实际页面脚本，覆盖 Dock、文件夹、删除撤回、布局、剪贴板回退、天气权限与扩展导航。

jsdom 不验证真实渲染、跨域权限、Canvas 解码、系统剪贴板和实际 Chrome 扩展安装。历史验证与这些限制保留在 [验证记录](verification.md)；`previews/` 内页面截图可能早于当前交互，不作为本次浏览器实测证据。

`scripts/build.mjs` 使用显式文件清单生成 `dist/qipage-startpage/`，包含主页所需的共享书签脚本及完整扩展。原始参考网页、依赖、测试数据与本地临时文件不进入发布包。增加运行资源时同步修改该清单。

## 维护方向

`app.js` 集中了状态、组件和网络逻辑，是后续维护的主要复杂度来源。新增功能应先把可独立计算和校验的逻辑放入 `core.js`，用行为测试保护数据格式；需要拆分交互模块时保留普通脚本与本地文件运行能力。发布整理阶段不进行大规模架构重写。

原始功能需求保留在 [需求记录](requirements.md)，实现与实际行为以当前代码和测试为准。
